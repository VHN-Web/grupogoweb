# GoWeb — instruções para IA (Claude / Cursor)

Plataforma SaaS **multi-tenant white-label** para restaurantes, bares e lanchonetes no **Paraguai**:
cardápio digital por QR, pedidos (mesa / retiro / delivery), pagamento multi-moeda (Gs., US$, R$),
caixa (PDV), estoque, registro de facturas e painel do estabelecimento. É um **site** (não app nativo).

Dois níveis:
1. **Plataforma** (dono: Lázaro) — `/admin`: planos, clientes contratantes, faturas multi-moeda,
   implantação → entrega → mensalidade automática → atraso → suspensão, domínios.
2. **Estabelecimento** (cliente do Lázaro) — `/{slug}` (cardápio) e `/painel/{slug}`.

Interface do cliente final, do painel do estabelecimento e das faturas em **espanhol (PY)**.
Admin da plataforma, comentários e docs em **português**.

## Stack
- Next.js 15 (App Router, Server Components, Server Actions) + React 19 + TypeScript strict
- Tailwind CSS v4 (tokens em `src/app/globals.css`; cor da marca via CSS var `--brand`)
- Drizzle ORM + PostgreSQL (dev local: PGlite em `./.pglite`; produção: `DATABASE_URL=postgres://...`)
- zod para validação; vitest para testes

## Regras invioláveis
1. **Isolamento multi-tenant**: toda query de dado de negócio filtra por `tenantId`. Toda Server Action do painel começa com `requireTenantAdmin(slug)`.
2. **Dinheiro**: cada estabelecimento tem uma **moeda base** (`tenant.currency`: PYG no Paraguai, BRL no Brasil). As colunas `*_pyg` de pedidos/produtos/caixa/notas guardam valores na **unidade menor da moeda base** (nome histórico: em BRL são centavos). Exceção: `invoices.amount_pyg/usd/brl` do billing são de fato por moeda. Cotações = "unidades da base por 1 unidade da moeda X" (`tenantRates`). Nunca use float para somar dinheiro; conversões só via `src/core/money.ts` (`fromBase`/`toBase`/`changeDue`), entrada de valores via `parseMajorToMinor`/`minorToInput`.
2b. **Região** (`src/core/region.ts`): `tenant.country` (PY/BR) define idioma (es/pt), moeda base, cotações, delivery e meios de pagamento padrão (`provisionTenant({country})`). Textos: `tr(locale)(es, pt)`; no painel use `panelI18n(t)`. Página de vendas detecta o país do visitante (`x-vercel-ip-country`/accept-language, `?lang=` força).
2d. **Exclusividade por país**: um estabelecimento/cliente do Brasil só vê português e R$ (sem Gs./US$, sem SIFEN/RUC); Paraguai vê espanhol com Gs./US$/R$. Moedas aceitas = `region.currency + region.extraCurrencies`.
2e. **Gateway do estabelecimento**: Mercado Pago (`src/adapters/payments/mercadopago.ts`) com o token DO estabelecimento, salvo em Configurações → Integrações (testado via /users/me antes de salvar). Opção sem credencial não aparece no site (`publicPaymentConfig`).
2f. **GoInteligence** (plano pro: `tenant.tier = "pro"`, definido por `plans.intelligence` na contratação ou pelo admin): sugestões (`core/intelligence.ts#buildSuggestions`), ofertas relâmpago (`products.promoPricePyg/promoEndsAt`, preço efetivo calculado no servidor), cupons (`coupons`, validados em `services/orders.ts`), carrinhos abandonados (`carts`, aviso ao lojista ao abrir o painel), agenda (`appointments` + `tenants.bookingConfig`, produtos com `durationMin`), equipe (`staff`, sessão `staff:<id>`, áreas em `PANEL_AREAS`; `requireTenantAdmin(slug, area)`), relatório de caixa (`services/intelligence.ts#cashReport`). Ações em `painel/[slug]/(app)/pro-actions.ts`.
2g. **Impressora térmica**: `/painel/[slug]/imprimir/[id]` (58/80 mm via `@page`), impresso por iframe (`components/ThermalPrint.tsx`); auto-impressão de pedidos novos se `tenants.autoPrint`.
2i. **Demos**: contatos sempre fictícios (+55 81 90000-00NN, Instagram genérico) e botões sem link; lojas `demo` nunca disparam WhatsApp/e-mail reais. **Login com Google**: `lib/google.ts` + `/api/auth/google` (env GOOGLE_CLIENT_ID/SECRET; admin só e-mails em PLATFORM_ADMIN_EMAILS; dono = e-mail do cliente ou `tenants.loginEmail`). **Movimento**: classes `anim-*`, `stagger`, `lift`, `btn-shine` e `[data-reveal]` + `RevealOnScroll` (respeitam prefers-reduced-motion).
2h. **Segurança (dinheiro)**: gateways simulados nunca confirmam pagamento real — billing `mock` só fora de produção; `mock_online` só em `tenants.demo`. Webhooks conferem valor/moeda (`>=` fatura/pedido). Cupom com `maxUses` incrementa de forma atômica. Tokens de gateway dos lojistas ficam criptografados (`lib/secrets.ts`, AES-256-GCM) — use `openCredentials`/`sealCredentials`. Logins e APIs públicas têm limite de tentativas (`lib/security.ts`, tabela `rate_limits`). Ações sensíveis chamam `audit()` (tela `/painel/[slug]/atividade`). Sessão versionada: trocar senha derruba outros aparelhos.
2i. **Contratos e recibos**: antes de pagar a implantação o cliente vê o resumo (`/fatura/[id]`) e precisa aceitar (`/api/billing/accept`, grava data/IP). Ao pagar, `services/documents.ts` gera o contrato (`core/contract.ts`, texto congelado em `contracts`) e o recibo/NFS-e (`service_invoices`), enviados por e-mail; links privados `/contrato/[id]?k=` e `/recibo/[id]?k=`. Retenção em `platform_settings.docsRetentionMonths` (cron diário; o contrato mais recente de cada cliente nunca é apagado). NFS-e: chave em Admin → Configurações, só liga com CNPJ + inscrição municipal + emissor; integração com o emissor ainda a implementar.
2j. **Idioma**: no Brasil tudo em português. Planos ficam cadastrados em PT (`planFeature`/`planName` traduzem nos dois sentidos). Mensagens de erro de API usam o país da loja/cliente, nunca texto misto "es · pt". Valores em campos do painel usam `components/forms/MoneyInput` (só números, máscara monetária).
2k. **Crescimento** (`core/growth.ts` puro + `services/growth.ts`): config em `tenants.growthConfig` (`parseGrowth`, `featureOn`). Base (todos os planos): carteira de clientes (`shoppers`, criado no pedido com WhatsApp), origem das vendas (`orders.source`, links `?origem=`), kit de divulgação (`/painel/[slug]/divulgacao`, `/painel/[slug]/material`, artes em `/api/kit/[slug]`), SEO (metadata + JSON-LD, `app/sitemap.ts`, `app/robots.ts`); opcionais: avaliação no Google e Vitrine da cidade (`/vitrine`). GoInteligence (opcionais): campanhas (`campaigns`, só clientes com opt-in LGPD), indique e ganhe (`?indicacao=`), fidelidade selos/cashback, aniversário (cron diário). Recompensas só quando o pedido vira COMPLETED (`onOrderCompleted`, flag `growthDone`); cupons pessoais (`coupons.shopperId`) só valem para o WhatsApp dono. Ações em `growth-actions.ts`; área de permissão `customers`.
2l. **Plano personalizado** (`core/modules.ts`): núcleo (loja online + pedidos, produtos, aparência, config) + módulos (mesas, delivery/motoboys, caixa, notas, impressora, divulgação, marketing✨, fidelização✨, agenda✨, equipe✨). Preços em `platform_settings.modulePrices` (Admin → Planos). Na contratação (`/contratar?plano=personalizado`) o preço é recalculado no servidor e vira um plano exclusivo (`plans.isCustom`, inativo, fora das listas). `tenants.modules` = JSON da lista (null = plano fechado, tudo liberado); `getPanelAccess` corta as áreas fora do plano (redireciona para `/plano?modulo=`), e `hasModule(t, m)` protege o resto (tipos de pedido, ofertas, agenda, impressão, crescimento, equipe). Admin troca módulos em Clientes → cliente (`setCustomerModules`).
2m. **Admins da plataforma**: senha-mestra do .env = sessão `platform` (principal); outros admins em `platform_admins` (e-mail + senha e/ou Google), sessão `platform:<id>@<versão>`. Só papel `owner` cadastra admins (`requirePlatformOwner`). Auditoria com o nome (`adminActor`). **Demonstrações**: Admin → Demonstrações (`services/demo.ts`) copia um modelo demo com tudo liberado (`demo=true`, `demoNote`), senha mostrada uma vez. **Motoboys** (módulo delivery, área `couriers`): `couriers`, `orders.courierId`, rota pelo WhatsApp (`core/couriers.ts`), acerto por período em `/painel/[slug]/motoboys`.
2n. **Painel (visual)**: navegação rápida — `loading.tsx` (esqueleto `components/ui/PageSkeleton`) no admin e no painel, transição `.page-in` curta, sessão deduplicada com `cache()` (`getPanelAccess`/`getPlatformAdmin`) e consultas em `Promise.all`. No tema escuro: abas ativas `btn bg-ink text-white`, QR sempre com `keep-light`. `PanelShell` (`painel/[slug]/(app)/PanelNav.tsx`) — barra lateral agrupada por área com cor própria (Vendas verde, Catálogo âmbar, Clientes azul, Gestão marinho; CSS vars `--section`/`--section-soft`), barra inferior no celular. Ícones SVG em `components/ui/Icon.tsx` — evite emojis na interface. **Upload**: `components/forms/ImageUpload` comprime no navegador (WEBP, até 1600 px) e o servidor confere o conteúdo (`adapters/storage`, Vercel Blob via BLOB_READ_WRITE_TOKEN ou BLOB_STORE_ID/OIDC; na Vercel sem Blob dá erro claro). **Acessibilidade**: `components/a11y` (texto maior, alto contraste, menos movimento, links sublinhados, espaçamento; classes `a11y-*` no <html>, salvas no aparelho), link "pular para o conteúdo" e foco visível. **Assistente**: `core/assistant.ts` (telas, ferramentas, filtro por área/módulo/pro) + `services/assistant.ts` + `/api/assistant` e `/api/assistant/confirm`; sem ANTHROPIC_API_KEY funciona como guia; com a chave usa ferramentas e TODA ação só roda após o botão Confirmar (token selado com `sealSecret`, validade 10 min, revalida permissão/plano).
2o. **Cobrança (política)**: na contratação só a implantação. Cada período começa na entrega/renovação e vence 30 dias depois (`core/billing.ts#periodDueAt`, `PAY_AFTER_DAYS`); `customers.nextBillingAt` = início do próximo período sem fatura. Na entrega não se gera fatura. Telas mostram o vencimento com `periodDueAt(nextBillingAt)`.
2p. **Suporte**: `support_tickets`/`support_messages`, `core/support.ts` (prioridade → SLA de 1ª resposta e solução, protocolo `GW-AAAAMMDD-XXXX`), `services/support.ts`. Lojista: `/painel/[slug]/suporte` (qualquer usuário do painel). Admin: `/admin/suporte` (fila por prazo, nota interna, muda prioridade/status). Avisos por e-mail/WhatsApp (nunca para demos).
2q. **Site oficial e rede**: `/` e `/planos` usam `components/site/*` (SiteHeader/SiteFooter/PlanCards; cores por CSS vars `.site`). **Shopping GoWeb** em `/shopping` (`services/network.ts`; lojas com `growthConfig.shopping` ligado, demos só enquanto houver < 6 lojas reais, sempre marcadas). Botão "Lojas parceiras" no rodapé de cada loja. **Tema** claro/escuro/sistema: `components/theme` (classe `dark` no <html>, salvo em `gw_theme`); painel/admin via CSS vars do Tailwind; lojas trocam a paleta do modelo (`.th[data-native]`).
2r. **Afiliados (só Brasil)**: regras puras em `core/affiliates.ts` (níveis Bronze 15%/Prata 17%/Ouro 20%/Diamante 22% por vendas pagas, 3% para quem indicou o afiliado — um nível só, +5% na 1ª anuidade do plano anual; config em `platform_settings.affiliateConfig`, editável em Admin → Afiliados → Regras; Pix copia e cola `pixPayload`). `services/affiliates.ts`: cadastro (CPF com hash + selado, fila da live = `affiliate_cohorts`, status PENDING→ACTIVE pelo admin), link `/a/CODE` (route: clique único/dia + cookie `gw_ref` 60 dias; `?ref=` no middleware também grava) → `/a/CODE/demo` (agenda = `affiliate_leads`). Atribuição em `createCustomer` (`attributeCustomer`: cookie, senão lead com o mesmo WhatsApp; só afiliado ATIVO, sem autoindicação). Comissão gerada em `markInvoicePaid` → `onInvoicePaidAffiliate` (base = implantação sem domínio, índice único fatura+afiliado+nível). Admin paga por Pix e marca como paga (`/admin/afiliados?aba=pagar`). Portal `/afiliados/*` com sessão própria (cookie `gw_aff`, `lib/affiliate-auth.ts`), visual gamificado em `components/affiliates`. Kit do afiliado (guia, textos com {link}/{nome}/{convite}) em `core/affiliate-kit.ts`; artes personalizadas com QR em `/api/afiliados/arte` (fonte Bricolage em `assets/fonts`, incluída via `outputFileTracingIncludes`).
2s. **CRM dos sócios (app /crm, instalável)**: PWA (`/crm/manifest.webmanifest`, `public/crm-sw.js` com push + tela offline, ícones em `public/crm/`), login = admin da plataforma (`/admin/login?next=/crm`; ator = id do admin ou "platform"). Regras puras em `core/crm.ts` (score Ouro/Prata/Bronze/Desq pelo link da bio + avaliações, detector de concorrentes, scripts por nicho, datas de Brasília, CSV). `services/crm.ts`: leads (`crm_leads`, dedupe por telefone/Instagram/nome+cidade), atividades (`crm_activities`: contato conta na meta), jornada (`crm_journeys`), painel "Hoje", métricas; importa os 35 leads do Lead Hunter na 1ª abertura (`src/data/crm-initial-leads.json`) e sincroniza a planilha (gviz CSV, aba "Leads CRM"). Integrações: indicação de afiliado → lead (`onAffiliateLead`), contratação → "Proposta" (`onCustomerCreated`), implantação paga → "Fechado" (`onSetupPaid`), chamado → push. `services/push.ts` (web-push, VAPID gerado sozinho e salvo em `platform_settings.crmConfig`). `services/crm-hunter.ts`: busca com o Gemini (chave do Lázaro em CRM → Busca, selada; `GEMINI_API_BASE` só para testes) + "Escrever com IA". Cron `/api/cron/crm` 3x/dia (vercel.json): retornos vencidos + busca. Abrangência em `core/br-geo.ts` (5.570 municípios via pacote `estados-cidades`, capitais, grandes cidades, 74 categorias em grupos); fila = prioritárias → capitais → grandes → demais municípios, cada cidade passa por todos os grupos de categorias (`huntPlan`/`nextHuntTargets`, cursor em `crmConfig`).
2t. **App do entregador (/entregador, PWA)**: `public/entregador-sw.js` + `/entregador/manifest.webmanifest` + ícones em `public/entregador/`. Acesso por link enviado pela loja (Motoboys → Enviar acesso; `couriers.accessHash` p/ busca + `accessSealed` p/ reenviar; "Gerar novo link" derruba o aparelho antigo), cookie `gw_cour` (`lib/courier-auth.ts`). `services/courier-app.ts`: online/offline, GPS (`/api/entregador/ping`, última posição em `couriers.last*`), entregas atribuídas, entregas livres (PREPARING/READY sem motoboy — quem pegar primeiro), "Saí" → OUT_FOR_DELIVERY (`orders.pickedUpAt`), "Entreguei" → COMPLETED (+ pago se recebeu; `orders.deliveredAt`), ganhos hoje/semana/mês (`courierEarning`: valor combinado ou taxa). Mapa ao vivo com Leaflet + OpenStreetMap (`components/maps/LiveMap`, polling): consumidor em `/[slug]/pedido/[id]` (`/api/rastreio/[id]`, só 1º nome do motoboy), loja em Motoboys e no pedido (`/api/painel/[slug]/frota`). Push reaproveita `crm_push_subs` com ator `courier:<id>` (`sendPush("all")` exclui entregadores). Regras puras (distância, ETA, ping, períodos) em `core/couriers.ts`. Limite: navegador só envia GPS com o app aberto (Wake Lock mantém a tela ligada). **Atribuição automática** (`tenants.dispatchConfig`, `parseDispatch`; padrão ligada, raio 5 km, máx. 2 por motoboy): ao entrar em preparo/pronto, `autoAssign` passa para o online com GPS ao vivo mais perto da loja (nota = km + 1,5 por entrega em andamento, `pickCourier`); também roda a cada ping. Motoboy pode recusar (`declineDelivery`, `orders.declinedCourierIds`) → vai para o próximo; atribuição manual zera `orders.autoAssigned`.
2u. **Imagens (Blob privado)**: a loja Vercel Blob da produção é privada — `saveImage` grava `access: "private"` e devolve `/uploads/<caminho>`, servido por `app/uploads/[...path]` com `get()` (cache longo). Se a loja for pública, cai para `access: "public"` e URL direta.
2v. **Asaas (Brasil) — subcontas + billing híbrido**: regras puras em `core/asaas.ts` (split com trava de teto `splitForSale`, ciclo de 30 dias + carência `cycleBounds`, `closeCycle`, eventos → status, CPF/CNPJ, chave Pix), cliente HTTP em `adapters/asaas/client.ts` (`ASAAS_API_BASE` só para testes), conta principal em `platform_settings.asaasConfig` (chave selada, walletId, token do webhook, `hybridEnabled`, % padrão, carência) — Admin → Configurações → Asaas conecta e cria o webhook sozinho; `adapters/asaas/runtime.ts` guarda a config em memória para o `isConfigured()` síncrono (preenchido em `getSettings`). Lojista: Painel → Recebimentos (`/painel/[slug]/recebimentos`, só BR) cria a subconta white-label (`tenants.asaas*`, chave selada; liga PIX/CARD com provider `asaas` + marcador `paymentConfig.credentials.asaas.enabled`), saldo, repasse por Pix (manual + automático diário no cron) e documentos pendentes. Checkout: provider `adapters/payments/asaas.ts` com a chave da subconta, CPF obrigatório, Pix com QR na página do pedido (`orders.pixPayload`), cartão pela página do Asaas; split calculado em `services/asaas#asaasCheckoutCredentials` (faltante = alvo − confirmado − reservado por vendas pendentes de até 2 h), gravado em `orders.platformSplitMinor/billingCycleId/splitStatus`. Plataforma: billing provider `asaas` (BRL, página do Asaas; CPF/CNPJ pedido na fatura se faltar; cartão usado → token salvo em `customers.cardTokenSealed`). Ciclos em `billing_cycles` (`runHybridBilling` roda antes do ciclo normal no cron: fecha, cobra o residual no cartão salvo ou manda link, suspende após a carência, abre o próximo; o 1º abre na entrega/criação da subconta). Clientes híbridos não geram fatura normal; faturas de residual ficam fora da carência genérica. Webhook único `/api/asaas/webhook` (header `asaas-access-token`, idempotência em `asaas_events`; `ord:` pedidos, `inv:` faturas → `markInvoicePaid`, que marca o ciclo `PAID_RESIDUAL`).
2w. **Geovana (IA no WhatsApp da loja, GoInteligence)**: regras puras em `core/geovana.ts` (config `tenants.geovanaConfig` com segredos selados, predefinições por nicho `GEOVANA_PRESETS` — só BR, prompt `buildSystemPrompt` só com dados da loja, marcações `[[CARRINHO: id:qtd]]` → carrinho em `carts` + link `?carrinho=` e `[[HUMANO]]` → pausa + "esperando a equipe", `orderNotice`). Canais em `adapters/whatsapp/`: `evolution.ts` (servidor Evolution da GoWeb — Admin → Configurações → Geovana: URL + chave global; instância `gw-<slug>` por loja, QR no painel; webhook `/api/whatsapp/evolution/{hookToken}`) e `cloud.ts` (API oficial da Meta com credenciais da loja; webhook `/api/whatsapp/cloud/{hookToken}` com verify token + X-Hub-Signature-256). IA: `adapters/ai/gemini.ts` com a chave da GoWeb (`platform_settings.whatsappConfig`) ou a própria da loja. `services/geovana.ts`: conversas em `wa_chats`/`wa_messages` (idempotência por id do WhatsApp; mensagem do lojista pelo celular = pausa a IA por `pauseMinutes`), contexto com catálogo, entrega, pagamentos e pedidos dos últimos 30 dias do número, avisos automáticos de status (hook em `setOrderStatus`), simulador no painel (`/painel/[slug]/geovana`). Webhooks respondem na hora e processam com `after()`. Demos nunca conectam.
2x. **Apps de delivery — Open Delivery (99Food, Keeta; só Brasil)**: padrão da Abrasel (spec em github.com/Abrasel-Nacional/opendelivery). A GoWeb é o "Software Service". Regras puras em `core/opendelivery.ts` (cardápio `buildMerchant` com UUIDs estáveis `stableUuid`, pedido `mapOdOrder`, status → ações `actionsForStatus` com confirm obrigatório antes, eventos `effectOfEvent`/`shouldApply` só avançam, assinatura `odSign`/`odVerify` HMAC-SHA256), HTTP em `adapters/opendelivery/client.ts` (OAuth client_credentials; Keeta: `X-App-Signature` em toda chamada; `orderURL` só do mesmo host). `services/opendelivery.ts`: canais `od_channels` (um por loja+app, segredo/token/apiKey selados, `merchantId` = CNPJ+UUID igual em todos os apps), onboarding (PUT merchantOnboarding com URL do cardápio + webhook), eventos com idempotência em `od_events`, pedidos com `orders.channel/externalId` (índice único), `marketplaceDelivery` (entregador do app: motoboys da loja não são chamados; "Pronto" → readyForPickup), `cancelRequestedAt` (cliente pediu para cancelar → loja aceita/recusa no pedido). `setOrderStatus(..., {fromChannel})` evita eco. Rotas públicas por loja: `/api/opendelivery/{hookToken}/v1/merchant` (X-API-KEY) e `/v1/newEvent` (webhook assinado, `after()`). Polling: quadro de pedidos (máx. 1x/25 s por canal) + cron diário. Mudou produto/categoria/aberto → `merchantUpdate` (`menuChanged` em actions.ts). Painel `/painel/[slug]/apps-delivery`; credenciais padrão da GoWeb em Admin → Configurações → Apps de delivery (`platform_settings.odConfig`).
2c. **Nome e telefone**: nome só letras (`sanitizeName`/`isValidName`, componente `NameInput`); telefone só dígitos com o tamanho exato do país incluindo DDD (`PHONE_RULES`, `PhoneInput`), salvo em E.164 e validado de novo no servidor (`isValidE164`).
3. **Preço e taxa SEMPRE recalculados no servidor** (`services/orders.ts`). Nunca confiar em valores vindos do navegador.
4. **Integrações externas só via adapter.** Nada de chamar Bancard/Pagopar/SIFEN direto de página ou service. Novo gateway = novo arquivo em `src/adapters/payments/` + registro em `registry.ts`. O resto do sistema não muda.
5. **Estoque**: baixa condicional dentro da transação do pedido (`stock >= qty`); cancelamento devolve via `stock_movements`.
6. **Credenciais** de gateway ficam em `tenant.paymentConfig.credentials` e nunca vão ao browser (use `publicPaymentConfig`).
7. **Billing**: faturas guardam o valor nas 3 moedas (definidos no plano, sem conversão). `markInvoicePaid` é idempotente e é o ÚNICO lugar que dispara efeitos (provisionar, reativar). Gateway por moeda em `platform_settings.gatewayByCurrency`.
8. O admin da plataforma (sessão "platform") acessa qualquer `/painel/{slug}`.
9. Novos valores de "enum" → adicionar em `src/core/types.ts` (e rótulos em `LABELS`).

## Ao implementar algo novo
- Regra de negócio pura → `src/core/` + teste em `*.test.ts`.
- Mudou o schema → `src/db/schema.ts` e rode `npm run db:push`.
- Rode `npm test && npm run typecheck` antes de concluir.
- Veja `docs/ROADMAP.md` para a ordem das próximas etapas e os pontos que exigem intervenção humana.
